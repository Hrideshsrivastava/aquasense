# AquaSense: from purifiers to intelligent water ecosystems

Everything for the Atomberg hackathon prototype in one project.

| Folder                | What it is                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------- |
| `demo/index.html`   | Stand-alone demo. Double-click to open in a browser. No install.                                               |
| `app/`, `static/` | The real backend (FastAPI) and its web app: Google sign-in, roles, telemetry, digital twin, tickets, fleet.    |
| `ml/`               | XGBoost (remaining life) and Isolation Forest (anomaly) trained on synthetic data. Pre-trained files included. |
| `simulator/`        | Purifier simulator and a demo-data seeder.                                                                     |
| `firmware/`         | ESP32 sketch (Arduino IDE). Untested on hardware.                                                              |

## 1. Fastest look (no install)

Open `demo/index.html` in Chrome. Pick a role (Customer, Technician, Atomberg admin) and explore. Everything runs in the browser on synthetic data. The assistant gives short rule-based answers here.

## 2. Run the full app (5 minutes)

You need Python 3.10 or newer.

**macOS / Linux:** `./run.sh`
**Windows:** double-click `run.bat`

The script creates a virtual environment, installs packages, seeds five demo purifiers and starts the server. Open http://localhost:8000.

On first run it makes a `.env` with `AUTH_DEV=1`, which shows demo sign-in links on the login page:

- `demo@example.com` is a customer with two purifiers
- `admin@example.com` is the Atomberg admin (fleet view, ticket updates)
- `tech@example.com` is a technician (technician tab, ticket updates)

Manual steps if you prefer:

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                  # set AUTH_DEV=1 for the demo links
python -m simulator.seed
uvicorn app.main:app --reload
```

Or with Docker: `docker build -t aquasense . && docker run -p 8000:8000 --env-file .env aquasense`

## 3. Live telemetry demo

1. Sign in as `demo@example.com`, open **My purifiers**, register a purifier and copy the device ID and key (shown once).
2. In a second terminal (venv active):
   `python simulator/simulate.py --id P-xxxx --key YOUR_KEY --fault pump --interval 2`
3. Refresh the page every few seconds. The pump health drops and the diagnosis changes to pump degradation.
4. Click **Book service**, then sign in as admin to see it in **Service** and the **Fleet** view.
   Other faults: `--fault membrane`, `--fault clog`, or none for a healthy purifier.

## 4. Real Google sign-in

1. Google Cloud Console > APIs & Services > Credentials > Create credentials > OAuth client ID > Web application.
2. Authorised redirect URI: `http://localhost:8000/auth/callback`.
3. In `.env`: set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, a long random `SESSION_SECRET`, your Gmail in `ADMIN_EMAILS`, technician Gmails in `TECH_EMAILS`, and `AUTH_DEV=0`.
4. Restart and click **Sign in with Google**. The first time, Google may ask you to configure a consent screen; add yourself as a test user.

## 5. ML models

Pre-trained models are in `ml/`. The **Twin lab** and each purifier card show an "ML check" line next to the rule-based result. To retrain: `python -m ml.train_models`.
These models learn from synthetic data generated by the rules, so they illustrate the pipeline. Their numbers are rough and are not a validated prediction. Real value needs real Atomberg service data.

## 6. ESP32 firmware

1. Arduino IDE > install the ESP32 board package. Open `firmware/aquasense_esp32.ino`.
2. Fill the CONFIG block (Wi-Fi, your computer's LAN IP in `API_URL`, device ID and key).
3. The sensor conversions are placeholders. Calibrate each against your real sensors before trusting any reading.
4. Readings go to the SD card first, then to the API when Wi-Fi is up. For anything beyond a bench test, use HTTPS.

## Troubleshooting

- Port 8000 busy: `uvicorn app.main:app --port 8001` and change `BASE_URL` in `.env`.
- Google error `redirect_uri_mismatch`: the redirect URI in Google Console must exactly match `BASE_URL/auth/callback`.
- ML line missing: run `python -m ml.train_models` (needs numpy, scikit-learn, xgboost).
- Reset data: stop the server and delete `aquasense.db`.

## Before real deployment

HTTPS with `BASE_URL` set to it, strong `SESSION_SECRET`, `AUTH_DEV=0`, Postgres instead of SQLite, rate limits on `/api/telemetry`, a security review, and consented anonymised telemetry. RUL is an estimate, not a water-safety certification.
